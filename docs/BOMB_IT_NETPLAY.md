# 《Q版泡泡堂7》原版联机验证

本文记录依据《SWF 联机工程指南 2.0》完成的原版适配。2～4 名玩家各自在浏览器里运行同一版本的 SWF，由房间服务器分配输入和确认逻辑帧。对局网络通道承载输入、就绪状态和检查点摘要。

## 接入决策

| 证据 | 对实现的影响 |
| --- | --- |
| 发行包 SWF 14 / AVM2，声明舞台 700×510 / 40 FPS | 每款游戏单独声明联机 tick；原版还会切换菜单帧率，因此用真实对局阶段验证逻辑节奏 |
| Ruffle Web 0.7.1 提供播放、暂停与 ExternalInterface | 用隔离页面控制时钟和动画帧，保留原版渲染；公开 API 本身无法直接导出对局状态 |
| 原版普通版支持同机 P1、P2，两个席位键位不同 | 网络层每席只接收自己的动作；适配器在执行双方确认帧时映射原版键位 |
| 原版游戏控制器存在可读的角色、格子和炸弹信息 | 用独立的 AS3 宿主加载未修改的 SWF，读取语义状态作检查点 |
| 发行 CDN 的 SWF 响应未提供跨域许可 | 大厅从同源版本化地址向两端提供已校验的原版文件，浏览器自动下载并核对指纹 |

Ruffle 的原版时间读取、动画泵和随机种子行为均受版本影响。升级运行时时应重新对照源代码并跑同一套输入记录。 [Ruffle 0.7.1 Web](https://github.com/ruffle-rs/ruffle/blob/v0.7.1/web/src/lib.rs) · [Ruffle 随机种子](https://github.com/ruffle-rs/ruffle/blob/v0.7.1/core/src/avm_rng.rs) · [播放器公开 API](https://ruffle.rs/js-docs/master/index.html)

## 已完成的通用房间改动

- `package.tickRate` 按游戏传递到房间协调器和浏览器桥。现有清单省略该字段时沿用 30 Hz。40 Hz 的间隔为 25 ms。
- 大厅可在同源 viewer 端口升级 `/lockstep`，复用原来的发票和席位校验。现有独立 lobby 端口仍可处理旧入口的升级请求。
- 本地 Chromium 双端测试通过 12 项，包括同源升级、40 Hz 配置、双端分别输入、同一客户端任务内短按、检查点、双方结算、失同步停止、重开和断线。

```powershell
node scripts/verify-lockstep.mjs
```

该测试使用项目自己的小型 Canvas 夹具。它覆盖房间到两个浏览器的真实连接路径，原版同步另需下节的原版状态证据。

## 原版状态实验

`experiments/bomb-it-netplay/BombItSnapshotProbe.as` 是自写的本地测试宿主。它通过 `URLLoader` 预取原包，等待同一时刻的启动信号再加载 SWF。两份实例都可以用 `F9` 在诊断输出读取角色位置、玩家生命和分数、地图格、炸弹引信和部分计时。内部计时器队列及随机数完整状态仍未导出，检查点不能用作存档或回滚。

大厅使用 v7 状态桥。它等待原版菜单构造完成，将房间选定的地图和模式交给原版 `UIManager` 的开场事件，等原版暂停面板显示后准备各个席位并调用恢复函数。第三、第四席沿用原版的出生位置和角色资源，在开局前交给原版真人控制器。2～4 席都由房间分配独立输入。对局按实际参战席位顺序传递角色、衣服、帽子和表情的原版编号。状态桥在开局前核对原版地图、模式和角色模型。Ruffle 的逻辑视口固定为 700×510，由外层页面缩放。默认以 700×510 渲染，宽屏且支持加速时按显示宽度以 1050×765 或 1400×1020 渲染。性能模式使用 350×255。画布分辨率在本局初始化时选定，缩放窗口期间仅调整显示尺寸。开场动画允许合并渲染回调，地图初始化和正式对局按 40 Hz 逐步驱动。播放器的主音量为 50%。

大厅提供原版九张地图和大乱斗、抢星星、吃金币、冰冻大战四种模式。地图与模式预览来自原版程序在浏览器中运行的实机截图。联机结算按对应模式的原版目标值判定，包括击倒数、星星数、金币数和冻结数。

原版 Flash 存档使用当前运行器的内存。页面刷新或重连需要重新启动运行器时，游戏从相同的空白原版存档和对局种子开始，再按服务器记录的输入推进。原版 SWF 的 IndexedDB 下载缓存由外层页面管理，可在重新启动时继续使用。

从仓库根目录运行，先使用项目已校验的 Apache Flex 4.16.1 和 Adobe PlayerGlobal 32.0 编译测试宿主。

```powershell
$flex = (Resolve-Path 'local/tools/as3-probe/apache-flex-sdk-4.16.1-bin').Path
$pg = (Resolve-Path 'local/bvn-candidates/ffdec-26.2.1/flashlib/playerglobal32_0.swc').Path
java "-Dflexlib=$flex/frameworks" -jar (Join-Path $flex 'lib/mxmlc.jar') `
  '-load-config=' "-compiler.external-library-path=$pg" '-target-player=11.1' `
  '-swf-version=14' '-static-link-runtime-shared-libraries=true' '-debug=false' `
  '-omit-trace-statements=false' `
  '-output=local/original-games/bomb-it/bomb-it-snapshot-probe-v7.swf' `
  'experiments/bomb-it-netplay/BombItSnapshotProbe.as'

node scripts/prepare-bomb-it-netplay.mjs
```

较低设备像素比缩小了软件渲染成本。两个独立 Chromium 实例在原版大乱斗、Boutique 地图和两名人类且无电脑对手的配置下进行回放。复核的四个对局状态摘要全部一致，覆盖开局、双方分别移动、各自攻击引发的道具变化、回合计时推进。大乱斗初始攻击使用原版锤子。普通炸弹、引信和连锁爆炸仍需在 Arcade 单独验证。原始记录保存在 `local/original-games/bomb-it/lockstep-state-duel-v3/`。

## 大厅预发布包

```powershell
node scripts/prepare-bomb-it-netplay.mjs
node scripts/verify-bomb-it-room.mjs --test-retry
```

对局页面自动从同源地址下载原版，在隔离页面加载前校验 8,740,427 字节和 SHA-256 `21ff6d4a2e442e97300ddb3f7abc73a4863a16f83b0b0769720b2fff0ab6d482`。校验通过后按指纹保存到同源 IndexedDB。后续开局先读取并验证浏览器存储，缓存失效时回到同源下载。共用的帧同步加载组件显示连接、缓存、下载字节数、校验、初始化和等待另一位玩家。下载失败后可以在当前对局的加载时限内点「重试加载」。对局使用同源 WebSocket，两个客户端分别提交输入与检查点，服务器确认同一帧的状态。

部署包带有 Ruffle 和自写的状态读取 SWF。启动大厅时可用 `--bomb-it-swf` 或 `BOMB_IT_ORIGINAL_SWF` 指定原版路径，默认从 `--shanyi-root` 下的 `bomb-it-7-original.swf` 读取。查看器仅在注册该游戏后处理固定的资源地址，在启动时验证并保存校验通过的原版字节。文件缺失或校验失败时，资源地址返回 HTTP 503，并在控制台记录原因。

本机双 Chromium 验收从确认开局到双方就绪约 24 秒。测试模拟了一端首次下载返回 502，验证重试后双端进入战场，状态推进到第 180 帧且检查点全部一致。再次打开同源页面时阻断 SWF 网络请求，仍能从本地缓存读取完整文件。两端播放器主音量均为 50%。

PCServer 发布 `20261127-bomb-it-7-preview` 后，经公网 FRP 大厅完成双 Chromium 冷启动。测试从确认开局到双方就绪约 24.8 秒，双方同步到第 180 帧并验证了无 SWF 网络请求的缓存重进。测试结束后，两端均通过大厅执行退出房间。

## 恢复对局和再开一局

连接中断后，服务器暂停分发新的输入帧并清空按住的动作，保留席位 20 秒。同一标签页重连时从已执行的帧继续。刷新会重新初始化相同的地图和装扮，再重放服务器留存的输入。服务器保留 12,000 帧历史，按 40 Hz 计算约五分钟。席位重新连上后最多有 60 秒追帧，追齐后全员继续。原版 Flash 存档在对局 iframe 内使用独立的内存存储，以免上一次加载留下的数据改变地图初始状态。页面仍可复用同源的原版 SWF 缓存。

结算页显示获胜席位或平局。对局内使用原版画面里的计分区。原参战玩家有两分钟同意再开，全员确认后按新种子开始一局，沿用角色、装扮和房间规则。

```powershell
node scripts/verify-lockstep.mjs
node scripts/verify-bomb-it-room.mjs --players 4 --width 1460 --dpr 1.2 --gpu --test-reconnect
```

本机四端测试实测 1400×1020 画布和约 40 逻辑帧每秒。强制断开后可以恢复原席，随后完整刷新仍能在第 240 帧完成一致性检查。公网发布 `20261127-bomb-it-7-reconnect-wardrobe` 后，双端通过同一路径验证了重连及缓存复用。原版在第 7170 帧结算为平局，两位玩家投票后在原席位进入下一局。大厅封面使用原版实机对局截图。

## 房间备战

房主从 9 张原版地图及 4 种对战模式中选择。备战区显示原版地图和模式截图，并从原版角色装扮界面导出的组合预览中显示当前角色、服装、帽子和表情。角色由房间服务按席位分配。服务逐条验证申请，拒绝给两个人分配同一个角色。调整自己的角色或装扮会取消自己的准备。房主变更模式或地图会增加规则版本，要求全员重新确认。

刷新房间时，席位令牌可以恢复服务器上保存的角色、装扮和准备状态。备战页断开后有 20 秒重连期，超过时限就释放角色和席位。房主超时后由在线席位中序号最小的玩家接任，再有人补位时继续由接任者管理。至少两人到齐且所有当前席位准备后开局。若刷新恰逢开局，认证后补发同一席位的对局地址。原版游戏实例从所有客户端共同收到的地图、模式、角色和装扮启动，并核对实际应用的设置。

```powershell
node scripts/verify-bomb-it-room.mjs --players 4 --width 1460 --dpr 1.2 --gpu --test-setup --test-reconnect --map Cake --mode collect
```

本机四端通过蛋糕地图和收集模式实测。公网 `20261127-bomb-it-7-room-setup` 用森林地图和吃金币模式跑通双端。两次都验证了准备状态和装扮在刷新后保留、原版运行器采用指定地图与模式、对局断线后通过第 240 帧状态校验。三个入口均返回新的预览资源和移除底部统计后的对局页。

### 原版菜单启动

原版加载画面曾异步请求 `Art_Res.swf`。该请求的回调会丢弃外部响应，再用 SWF 内置素材创建加载画面。如果原版主程序先完成加载，清理函数会提前返回，导致进入主菜单的 `A10` 事件没有触发。三人 Chromium 测试延后该请求六秒，复现了「原版主菜单未能就绪」。

兼容层在校验原版文件后，在内存副本中同步调用原版内置加载画面的构造逻辑。接下来的菜单和地图仍由原版流程初始化。新版本在同样的网络延迟模拟下能开局，浏览器也无需请求 `Art_Res.swf`。

公网 `20261127-room-ready-and-input` 用三个 Chromium 玩家在教室地图和吃金币模式开局。三个浏览器均走内置加载画面，约 24.8 秒进入对局，到第 180 帧的检查点一致。发布后另用两个大厅连接验证关页超时。约 20.2 秒后 P1 席位释放，P2 接任房主，新玩家进入 P1 后仍由 P2 选择地图。

## 每帧耗时和障碍物回归

旧版双窗口在软件渲染、DPR 1 下约 2～3 个逻辑帧/秒。v5 选择原作内置的二维绘制路径，Ruffle 继续提供 `BitmapData.draw`。当时画布像素比上限为 0.5。新版默认以原生 700×510 渲染。启用硬件加速时，对局显示宽度达到 875 和 1120 个物理像素会分别使用 1050×765 和 1400×1020。服务器用单调时钟调度 25 毫秒的逻辑帧并保留同样的确认机制。验收脚本记录真实帧率、画布实测尺寸和单帧处理耗时。

原版锤击在生成破坏特效后对 Proxy 调用 `hasOwnProperty`，Ruffle 抛出 #2091，拦住了后续的贴图和格子清理。`compatibility.mjs` 验证原包指纹后，仅在内存副本中把这处判断改成原版同类代码使用的 Proxy 类型测试。障碍物回归用游戏键位进行真实锤击，对照实时格子、原版破坏积分和击打前后的实际像素。

```powershell
node scripts/verify-bomb-it-room.mjs --players 4 --dpr 1 --gpu
node scripts/verify-bomb-it-obstacles.mjs
```

`20261127-bomb-it-7-multiplayer-tank-hud` 的本机三人测试约 40 个逻辑帧/秒，公网四人测试约 39 个逻辑帧/秒。Chromium 测试启用了硬件加速并以 DPR 1 打开页面。每个客户端按服务器实际分配的席号移动自己的角色，所有检查点同步到第 180 帧。固定种子的真实锤击在第 30 帧释放障碍格，后续检查中障碍保持为空并获得 10 点原版破坏积分，目标贴图区域 400 像素中有 122 像素发生明显变化。
