# 森林冰火人源码审计与关卡提取实验

审计日期：2026-11-17。对象是本次上传的文本源码包中 `02-fireboy-watergirl`，重点为第一代 Flash 反编译代码。本文记录静态源码证据与实际执行的提取测试；没有把数据提取称为原游戏运行、联机兼容性或物理一致性测试。

## 1. 可以立即复用什么

第一代的关卡矩阵、出生位置、出口参数、机关创建参数可以安全提取，已实际完成 **32 个正式关卡、36,192 个地图单元、64 个出生点、64 个出口参数和 316 次机关/出口工厂调用** 的提取及结构检查。另有一个独立的开发测试关，默认不混入正式关卡。

原有键盘控制也有明确接口：`Game.as` 将键盘状态写进 `level` 的六个布尔量，`level.Update` 消费它们。因此，把房间输入接到游戏逻辑上有具体改造位置。但 `level.Update` 同时操作 Box2D、显示对象、音效、机关和通关动画；它不是一个可直接在 Node.js 调用的纯模拟函数。

当前包中没有可播放的 SWF、JavaScript 游戏运行文件、图片或音频。第一代 `level.as:22` 的 Embed 元数据引用 `/_assets/assets.swf`，这份资产也不在当前包内。因此，尚不能据此重建并实测原版完整游戏。C++ 重制和 HTML5 关卡文件也存在明确缺件，见后文。

## 2. 输入、时钟与状态的实际接口

本节简写 `Game.as`、`level.as`、`ContactListener.as` 均相对于：

```text
02-fireboy-watergirl/decompiled/1-export/script/scripts/
```

| 项目 | 源码证据 | 联网改造含义 |
| --- | --- | --- |
| 游戏入口 | `Game.as:906` 的 `StartGame`，在 `934` 创建 `new level(mode, number)` | 房间应协商同一个游戏版本、模式和编号，再一致地创建关卡 |
| 火娃输入 | `Game.as:663–704`、`822–843`；方向上/右/左分别写 `u_pressed`、`r_pressed`、`l_pressed` | 可映射为角色独立的 jump/right/left 逻辑位 |
| 水娃输入 | 同上；W/D/A 写 `u_pressed2`、`r_pressed2`、`l_pressed2` | 服务器按座位校验输入所属角色，无需共享系统键盘 |
| 持续与边沿 | `level.as:1440–1450`、`1587–1596`；跳跃要求按住 jump、可落地跳跃、且 `prohibjump` 为 false；松开后清除 prohibit | 必须保留松开事件和跳跃锁存状态，不能把网络重复包当成新的跳跃 |
| 暂停 | `Game.as:663–704`；P 切换暂停，暂停分支清六个输入 | 暂停是房间级命令；一人自行暂停会导致状态分叉 |
| 调度 | `level.as:929` 监听 `Event.ENTER_FRAME`，`1804` 调用 `m_world.Step` | 外部逐帧控制需要接管完整游戏更新，不能只调用 Box2D |
| 舞台频率 | `Game.as:23` 声明 25 FPS | 原版调度与物理积分步长不是同一个数字 |
| 物理步长 | `level.as:76` 为 `1 / 26`，`52` 为迭代数 50 | 移植或回放先保留原值；直接换成 60 Hz 会改变操作和机关行为 |
| 重力与比例 | `level.as:188–194` 为 `(0,26)`；`2035–2060` 将物理位置乘 20 写到显示对象 | 工厂坐标与渲染像素不可混用 |
| 成绩计时 | `Game.as:328–357`、`947` 使用 `getTimer()` | 网络等帧时间、暂停和重连要有明确计时规则 |
| 帧计数 | `level.as:1598` 增加 `timecount`，`1657–1658` 用其驱动风力正弦项 | 同样的输入必须在同一个逻辑帧生效 |
| 通关 | `level.as:1705–1730` 检查两扇门的 `MovieClip.currentFrame == 22` | 通关依赖动画状态；仅同步角色位置不完整 |
| 接触事件 | `ContactListener.as:58–88` 处理死亡，`101–153` 处理钻石、声音、显示对象删除和形状销毁 | 需要稳定的对象 ID、事件去重和可恢复的收集状态 |
| 存档 | `Game.as:562` 使用 `SharedObject.getLocal("FBCookie")` | 解锁与成绩不能由每台浏览器各自决定同一房间的关卡状态 |

移动实现也不是常见的“每帧 x 加一个固定值”：`level.as:1379` 起的方向分支限制速度，沿接触面法线施力，转向时增加力；跳跃分支施加冲量并把纵向速度设为 `-13.5`。单纯根据源码里的起点、速度常量写一个 AABB 小游戏，不能宣称还原了原版 Box2D 手感。

第一代 `Game.as` 的鼠标处理主要对应选关、菜单、重试、静音等界面命令，已审计的双角色移动使用上述六个键位。平台应传 `selectLevel`、`retry`、`pause` 等明确命令；没必要把它们变成跨机器共享鼠标指针。

## 3. 关卡提取器做了什么

实现文件为 `scripts/audit_fireboy.py`。它只使用 Python 标准库读取文本和 JSON，不运行来源包里的 Python、AS3、构建脚本或游戏代码，不调用 `eval`。

解析器只接受已确认的数据语法：数字、双引号字符串、布尔值、`new Array(...)`、`new b2Vec2(x,y)` 和三个经源码绑定核对的钻石符号。`Math.random()`、属性访问、任意函数或未知构造器均不会执行。AS3 的单个数字 `new Array(3)` 表示数组长度，不会误读成 `[3]`。

输出保留模式、编号、源代码行号、地图矩阵、两角色出生点、出口输入向量和各工厂调用参数。需要注意：`CreateFinish` 的第一参数为火娃出口，第二参数为水娃出口；原工厂在创建 Box2D body 时还把 y 加 `0.66`（`level.as:1175` 起）。JSON 中的 exits 是原始工厂参数，不能直接视为最终 body 中心。

这是针对当前反编译文件布局的受限数据解析器，不是完整 AS3 解析器。未知关卡语法会失败退出；可读出的未知瓦片和工厂名会进入 `unsupported`。矩阵不规则、缺出生点、重复关卡 ID 也会报错。它不运行工厂、不生成 Box2D fixtures，也不声称实现其中的滑轮、杠杆或风场。

### 地面语义由原 AS3 分支确定

依据 `level.as:2517` 起的 `CreateGround`：

| 原 AS3 数值/符号 | 已核实含义 | 主要分支位置 |
| --- | --- | --- |
| `0` | 没有匹配的创建分支，作为空单元 | `CreateGround` 各分支 |
| `1` | 方形静态碰撞块 | 2603 |
| `-1`、`-2`、`-3`、`-4` | 四种三角形碰撞块，顶点写入提取元数据 | 2642、2665、2690、2715 |
| `"bd"`、`"rd"`、`"gr"` | 蓝钻、红钻、共享银钻 | 2559、2574、2589 |
| `5`、`51`、`52` | 水池中段及左右端 | 2741 起 |
| `6`、`61`、`62` | 火池中段及左右端 | 2873 起 |
| `7`、`71`、`72` | 黑池中段及左右端 | 3005 起 |
| `4` | **unsupported：adventure-5 有 1 个，未赋予碰撞语义** | 原矩阵中保留；没有对应的已核实创建分支 |

池子包含传感器和实体底部/边缘 fixtures。把所有非零单元都当成实心墙，或者把整个池格都当成纯伤害区域，均会改变原游戏碰撞。提取的语义标签只是后续移植参考。

关卡内出现 `4` 的事实保留在输出，不偷偷把它变成墙或删掉。任何消费这些关卡的运行器都应明确处理 `unsupported` 后再允许载入。

## 5. 其他现有材料能否替代原运行时

### HTML5 JSON

`html5-online/games/1-forest-temple/data/forest/levels/` 确有 Tiled 风格 JSON，例如 `forest_02.json` 是 39×29、tile size 32，包含 Ground/Chars/Objects 等层。但它引用 `../../../assets/tilemaps/tilesets/Ground.json`、`Chars.json`、`Objects.json`；其他关卡还引用 `LargeObjects.json`。当前包没有这些 tileset 定义，也没有运行游戏的 JavaScript。

这些 HTML5 GID 与原 AS3 的 `0/1/-1/5/51/...` 不是同一套编号。没有 tileset 元数据或原运行代码时，不应根据数字相近去猜测碰撞、机关或角色含义。本实验因此只提取已经有明确语义来源的第一代 AS3。

### C++ 重制

`cpp-remake/README.md:84` 将其描述为 OOPL2024s 项目，使用 PTSD Template。`CMakeLists.txt:4` 指定 C++17，`14` 拉取 PTSD，`25` 引入 `files.cmake`，`48` 引用 `Resources`，`59–60` 链接 SDL2/PTSD。

当前源码包同时缺 `files.cmake` 和 `Resources/`。它是另一套实现，不能以名字相似就视为原 Flash 的完整引擎，亦不能据当前包宣称能成功构建或保留原版玩法。将它编译为 WebAssembly 还会是另外的移植工作。

### TAS 工具

`tas-src/README.md:5–9` 描述按帧控制序列和 SWF 字节码注入，可证明原游戏输入有可仪器化的切入点。它不是通用联网适配器；现有 `mod.py` 针对预期的 SWF/字节码字段工作，还依赖外部拆装工具。此次只读其源码，没有执行。

## 6. 对接路线与仍需验证的项目

如果目标是保留原游戏，最少改玩法逻辑的候选路线是：补齐获准使用的 SWF/资产与可重建链路，围绕原 AS3 增加逻辑输入桥接和受控帧更新，再验证浏览器运行环境。需要明确处理第一代 `Game.as:549–553` 的发行站点绑定：当前代码会根据 `loaderURL` 决定是否把整个 Game 移出可视区。这是实际部署依赖，不能把缺件或站点绑定误判为网络协议问题。

桥接验证应先在同一固定运行时里运行相同关卡、种子和输入，比较每帧的角色、机关、接触状态、钻石、暂停/死亡/通关状态及关键 MovieClip 帧。之后再比较不同浏览器和后台切换情况。若只记录 `x/y/vx/vy`，不能支持可靠回滚，因为机关关节、接触缓存、跳跃锁存和门动画等状态未恢复。此处只是验证计划，**尚未证明 Ruffle 或其他运行时可对本包无修改保持跨客户端确定性**。

如果转向原生 Web 游戏引擎，当前提取器提供可追溯的内容输入，但仍需逐项移植 Box2D 几何、机关、接触事件、动画控制和关卡结果，并以原版录制轨迹对照验证。初期可仅选一个小范围关卡做垂直测试；未实现的工厂必须显示为不支持。用简化方块世界验证房间协议是有效的网络实验，但应明确标成平台实验，不能表示 32 个原关卡已经完成移植。

本次完成边界：源码审计、明确的输入/时钟接口、32 关安全提取、13 个解析器测试及真实数据结构检查。未完成边界：原 SWF 运行、资产恢复、编译、联网后的原版物理/动画一致性、完整原生移植及公网性能压测。
